# Future: 충전금(예치금) 기반 주문/결제 구조

아직 구현하지 않는다. 공급처 자동주문과 분리해서 설계한다.

향후 범위:

- 고객이 충전금을 미리 충전한다.
- 주문 시 충전금 잔액을 확인한다.
- 잔액이 충분하면 주문 가능 상태로 진행한다.
- 주문 확정 시 충전금을 차감한다.
- 잔액 부족 시 주문을 차단하거나 충전 안내를 표시한다.
- 관리자 화면에서 충전, 차감, 환불 내역을 확인한다.
- 모든 충전금 변경은 ledger 방식으로 기록한다.
- 실제 PG 연동, 입금 확인, 환불 자동화는 별도 후순위로 둔다.
- 공급처 자동주문과 충전금 차감은 같은 트랜잭션으로 묶지 않고 상태 기반으로 분리한다.

# Phase 4 Future Auto Order

## 현재 상태

MVP에서는 자동 발주를 구현하지 않는다.

## 향후 원칙

- AdminPlus 자동주문은 제외한다.
- 공식 API 또는 공급처 허가가 있는 곳부터 검토한다.
- 예치금 방식은 선충전 후 주문 상태 확인 위주로 설계한다.
- 결제/보안 인증 우회는 구현하지 않는다.
